## 1. P0 必须拍板（产品/技术歧义）

### 1.1 播放「让出」的判定边界 ⚠️ 高

| 未决 | 选项 | 建议默认 |
|------|------|----------|
| 什么算播歌？ | 仅音乐 App / 任意 MediaSession / 含导航播报 / 含视频 | **活跃 MediaSession 且 isPlaying**；**排除**明显非娱乐（若能读 category）；拿不到 category 则「凡 playing 都让出」（宁可多让） |
| 蓝牙电话 | 让出 / 不让 | **让出**（安全） |
| 导航语音 TTS | 让出 / 不让 | **不让出**（难区分时跟 playing 走 → 可能误让，P0.5 再优化） |
| 无 NotificationListener 授权 | 无法检测 | **视为未播歌**（可上壁纸）+ 设置入口引导授权；**不要**因未授权拒绝上壁纸 |
| 检测通道 | 仅 NLS / 仅 MediaSession / 双通道 | **优先 MediaSession 活跃会话**；NLS 作补充；**禁止 READ_LOGS** |

**缺文档**：交互只写了「检测到歌曲播放」，未写误判策略与未授权降级。

### 1.2 开机恢复方案 A 的细则 ⚠️ 高（刚定方向，细则未写全）

| 未决 | 建议 |
|------|------|
| 与「空闲显示」完全绑定 | ✅ 已定 A：空闲关 → 不 boot 上屏；空闲开 → 调度 recover |
| 恢复时机 | `BOOT_COMPLETED` + `USER_UNLOCKED`/`USER_PRESENT` + 延迟 2.5s/8s/20s（对标 Lyra） |
| 开机时正在播歌 | **不上屏**，只保进程/听媒体，停播后再上 |
| 进程被杀（非开机） | 需 **轻量 FGS 或至少 NLS 绑活**？见 1.3 |
| 从未打开过 App | 帮助写清「安装后请打开一次」；依赖厂商是否允许纯 BOOT |
| 失败骚扰 | 开机失败 **禁止弹窗**；进 App 再提示 |
| 设置文案 | 不单独开关；空闲显示的副文案补一句「开启后将在车辆启动后尝试自动恢复」 |

### 1.3 前台服务 / 常驻通知形态 ⚠️ 高

文档既写「避免重型 FGS」，又要：开机恢复、播歌让出、停播夺回 → **进程必须在关键时段存活**。

| 未决 | 建议 |
|------|------|
| 是否 FGS | **要轻量 FGS**（类型偏 `mediaPlayback` 或 `specialUse` 需合规评估；对标 Lyra 用 mediaPlayback） |
| 通知文案 | 「星澜正在保持星环壁纸」· 点进 App；**不可静默无通知**（系统限制） |
| 空闲关时 | **停 FGS / 不停监听？** 建议：空闲关 → 释放屏 + **可停 FGS**；用户再开空闲 → 再起 |
| 与播歌 | 播歌让出时 **FGS 可仍在**（为了听停播），文案可改为「播歌中已让出星环」 |

**缺文档**：通知文案、起停条件状态机。

### 1.4 与 Lyra / 原厂 RemoteScreen 争屏 ⚠️ 高

| 未决 | 建议 |
|------|------|
| 双开优先级 | 文案已有软提示；技术上 **星澜播歌让出** 已降低冲突 |
| 空闲时双开都抢壁纸 | **后启动者覆盖**；帮助写「请勿同时开两套占星环」 |
| 原厂抢回 | 检测丢失后是否自动再占？建议：空闲开且未播歌时 **有限次重试**（对齐 boot 延迟），避免死循环打日志 |
| 包名互知 | 可选 `queries` Lyra 包名，About 检测「已安装 Lyra」加强提示 |

### 1.5 权限与首次引导节奏 ⚠️ 中高

| 权限 | 何时要 | 拒绝后 |
|------|--------|--------|
| 存储/媒体 | 导入时 | 可走 Download 说明 |
| **通知使用权** | 首次需要播歌检测时，或设置「播歌让出」说明入口 | 降级：无法让出，设置黄字「建议开启以便播歌让出」 |
| 通知（POST） | FGS 时 | 可能影响保活展示 |
| 自启动/电池优化 | 设置/帮助链出，非强制弹窗轰炸 | 不授权则开机不稳 |

**缺交互**：首次「应用当前」成功后，是否引导开通知使用权？（建议：**第二次进 App 或首次播歌误占时再引导**，避免首启过重）

### 1.6 包名 / 签名 / 安装渠道 ⚠️ 中（工程开工挡）

| 未决 | 建议 |
|------|------|
| applicationId | 例如 `com.starlive.app` 或 `xyz.998618.starlive`（与 Lyra 体系一致则跟你现有域名） |
| 签名 | debug 开发；release 独立 keystore，**勿与 Lyra 混用**除非刻意同签 |

| minSdk / 车型 | 写明目标：**阿维塔 + 华为座舱星环可 launch 的机型**；其它「尽力」 |

## 4. 测试与验收缺口

现有验收偏「happy path」，建议补 **实车矩阵**（写入后可作为 QA）：

| 场景 | 期望 |
|------|------|
| 冷启 + 空闲开 + 未播歌 | 20s 内壁纸恢复（允许重试） |
| 冷启 + 空闲开 + 已播歌 | 不占屏；停播后上屏 |
| 冷启 + 空闲关 | 不占屏、可不拉 FGS |
| 行驶中播歌/暂停 8s+ | 让出 / 夺回 |
| 切歌空隙 <3s | 不闪壁纸 |
| 与 Lyra 同机、Lyra 总开关开 | 播歌时星澜让；行为可接受不崩溃 |
| 关空闲再开 | 立即或恢复上屏 |
| 杀进程后亮屏 | 能恢复或进 App 一键好 |
| 无 NLS 权限 | 壁纸仍可上；让出可能失效并有提示 |
| Display 不可用机型 | 「无法上屏」人话，不 ANR |
| 导入 1×1 / 30MB / 损坏文件 | 错误 Sheet |
| 4032×284 与 2990×284 导入 | 裁切符合规格 |

**缺**：性能（内存、掉帧）、整夜停车后再开、双用户（若有）。
